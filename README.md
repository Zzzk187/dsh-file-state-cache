# dsh-file-state-cache · 文件状态缓存

[English](README.en.md) · **简体中文**

> 让 AI 记住「这个文件我读过」，第二次别再从头读一遍。

这是一个 DSH 插件（也是一个技能）。装好之后，Agent 读文件就「有记性」了。

---

## 它能帮你省什么

平时 Agent 改个文件常常这样绕：`看目录 → 搜关键词 → 打开全文 → 改完再打开全文确认`。大半是重复劳动。装了它之后：

| 以前 | 现在 |
|---|---|
| 找代码要连着试好几步 | 一句 `explore "关键词"`，直接告诉你文件、行号、下一步读哪 |
| 同一个文件反复读全文 | 第二次只回一句「内容没变」 |
| 改完再读全文确认 | `edit` 直接回改动 diff + 第几行 |
| 想看懂一个目录 | 一句 `digest`，列出每个文件的函数签名 |

省下来的是 **AI 的上下文（token）**，代价只是硬盘上一点缓存。

> **一句话**：同一件事要做第二遍，用它；只做一遍，用系统自带的读文件就行。
> 注意它省的是 token，**不是时间**——每次调用仍要起一个小进程。

## 安装

```bash
dsh plugin --profile web add Zzzk187/dsh-file-state-cache
```

- **Windows 10 / 11**（本项目只针对 Windows 维护，不支持 Linux / macOS）
- 需要 **Python 3.8+**，不用装任何第三方包
- 装完技能列表里会多出 `file-state-cache`

---

## 30 秒上手

```bash
F="<包目录>/scripts/fstate"             # 技能会告诉你包在哪
"$F" explore "handleRequest" --root .    # 找代码
"$F" read src/app.py                     # 第一次给全文，第二次给「没变」
"$F" edit src/app.py --old 'return 1' --new 'return 2'
"$F" digest src/                         # 看目录结构
```

`<包目录>` 一般是 `~/.dsh/profiles/<profile>/node_modules/dsh-file-state-cache`。跑一下 `python "<包目录>/scripts/fstate.py" -h` 能出帮助就对了。

`read` 会自己判断该给什么：

| 情况 | 给你 |
|---|---|
| 第一次读 | 全文 |
| 读过、没变、这个会话里已经给过全文 | 一句「内容没变」（不再吐正文） |
| 读过、但文件被改了 | 只给 diff + 改了第几行 |

`edit` 改完直接给 diff，**看这个 diff 就是确认，不用再读一遍**。

## 命令一览

| 命令 | 干什么 |
|---|---|
| `explore "关键词"` | 找代码在哪 |
| `read 文件` | 带记忆地读；没变给摘要，变了给 diff |
| `read 文件 --mode range --start 40 --end 90` | 只读某几行 |
| `edit 文件 --old 旧 --new 新` | 改一处，回 diff |
| `write 文件 --content-file 内容文件` | 整篇写入 |
| `digest 目录/` | 多个文件的结构总览 |
| `state 文件` | 查看这个文件的缓存状态 |
| `diff 文件` | 看上次的完整 diff |
| `reset 文件` | 清掉这个文件的缓存 |
| `hot` | 看自己在反复读哪些文件 |

`--help` 看全部参数。常用的几个：

- `--mode full`：明确要全文
- `--brief`（`explore` / `digest`，1.1.1 起）：只给「文件 + 命中行 + 下一步」，省掉装饰性输出；定位信息和所有 ⚠ 警告都保留。不加这个开关时，输出和旧版完全一样
- `--label "名字"`：用短名字代替长路径

## 两件要知道的小事

1. **大文件一次给不完**：默认最多 400 行 / 20000 字符，超了会**明说「不算读过」**并告诉你接着怎么读，绝不会拿一句「内容没变」糊弄你。确实要把整篇交给 AI，请显式写 `read 文件 --mode full --max-chars 100000`。
2. **「内容没变」只在同一个会话里算数**：换了会话（`DSH_SESSION_ID` 变了）会重新给全文。拿不准就 `reset` 一下。这是故意的——省上下文不能变成「让你以为自己看过」。

它怎么判断文件变没变？每次读之前先核对磁盘上文件的「指纹」，不一样就按「被改过」处理；万一连上次的原文备份都丢了，会老实说「我没有基线」并给全文，**绝不假装知道改了什么**。

## 常见问题

**会不会读到旧内容？** 不会，每次读之前都先核对指纹。

**会不会改坏文件？** 不会。BOM、编码（UTF-8 / GBK 等）、换行（CRLF / LF）都原样保留；写入失败会回滚，不会留下半个文件。

**缓存脏了 / 想从头来？** `reset 文件` 清一个；删掉 `~/.dsh/fstate-cache/` 全清，无害，下次自动重建（`FSTATE_HOME` 可换位置）。

**占多少硬盘？** 每个文件几百字节，外加一份原文备份（≤ 2 MB，且只有真读过的才有）。

**大文件 / 二进制呢？** 超过 8 MB 或二进制文件按设计拒绝，请改用系统自带的工具。

## 排错（最常见的几条）

| 看到 | 怎么办 |
|---|---|
| `未找到 old 片段` | `--old` 和文件对不上（空格 / 缩进），用 `read --mode range` 把原文复制出来 |
| `old 片段出现 N 次，不唯一` | 多带一行上下文，或确实要全改就加 `--all` |
| `找不到 python` | 设 `FSTATE_PYTHON=/路径/python` |

退出码：**0** 成功、**2** 失败、`edit` 没找到 / 不唯一 **3**、Ctrl-C 中断 **130**。
