# dsh-file-state-cache · 文件状态缓存技能

[English](README.md) · **简体中文**

> 让 Agent 的「读文件」变成**有记忆**的动作 —— 读过的文件不再整篇重读。

`ls` 一轮 → `grep` 一轮 → `read` 一轮 → 改完再 `read` 一轮确认。四轮里三轮是在问自己"我刚才是不是看过了？"。本技能把这一串压成一次探索、一个会记住自己发生过的读、以及一个改完直接回 diff 的编辑。

---

## 它到底省什么

| 浪费 | 以前 | 用了之后 |
|---|---|---|
| **探索往返** | `ls`、`grep`、盲目 `read` —— 三轮 | 一次 `explore "关键词"` → 按相关度排序的命中文件（带**定义行号**）+ 命中行 + 签名 + 片段 + 下一条该跑的命令，约 1.5 KB |
| **重复读未变的文件** | 每次都是全文 | 一行字：*「内容未变，此前已读 N 次，最近读的范围…」* |
| **改完还要验证** | 重读整个文件 | 统一 diff + **精确**的变更行区间 |
| **读 N 个文件才看懂结构** | N 次读 | 一次 `digest` → 一屏 N 个签名 |

状态存在**磁盘上**，不占上下文。这是关键：它能跨工具调用、跨轮次、跨重启活着。普通的一次性工具调用做不到，所以本技能做成「CLI + 技能」，而不是注册一堆工具。

**实测（在一个 115 文件的 TypeScript 项目上，538 次真实查询）**：`explore` 一次平均输出 1.4 KB；答案文件排第一的比例 93.6%，前三 100%。同一文件在会话里被碰 4 次省 65%，改 N 处各确认一次稳定省 88%。但**只读一次就完事的一次性任务它是亏的** —— 详见下文[什么时候别用](#什么时候别用)。

## 它是怎么「记住」的（解释说明）

这一段是给想知道原理的人看的，不想看可以跳到[安装](#安装)。

### 问题不在「工具不够」，在「工具不记事」

一个插件可以给 Agent 注册 `read_file_smart`、`get_last_diff` 这样的工具，但**每一次调用都是全新的一次**：工具函数被调用时拿到参数、返回结果、结束，函数体内的变量随调用结束一起消失。所以哪怕注册了缓存工具，第二次调用时它依然不知道第一次读了什么 —— 除非它自己去别处读状态。

也就是说，**"记住"这件事必须有地方存**。能存的地方只有三个：

| 存哪 | 活多久 | 问题 |
|---|---|---|
| 模型上下文 | 到下一次压缩/换会话 | 正是它想省的东西，越存越挤 |
| 插件进程内存 | 到插件重启 | 换会话、重启就没了；且模型看不到它 |
| **磁盘** | 一直在 | 无 |

本技能选第三个。这也是为什么它是个**命令行脚本**而不是一组注册工具 —— 命令行进程本来也无状态，但**磁盘给它续了命**：第 N 次调用时，它去 `~/.dsh/fstate-cache/` 里翻上一次留下的记录。

### 一条记录里存了什么

每个文件一条 JSON，文件名是路径的 SHA-1 前 20 位（避免路径里的冒号、斜杠在不同系统上出问题）：

```json
{
  "path": "D:/proj/src/app.py",
  "version": 3,
  "sha1": "…",
  "read_count": 2,
  "last_read": "2026-11-03T14:02:11",
  "last_read_range": ["1..19"],
  "last_edit_range": [14, 14],
  "shadow": true
}
```

外加一份 `.shadow` 影子副本（≤2 MB 的文件才有），内容是**上次读到时的原文**。没有它就没法算 diff —— 总不能要求用户装 git 才能看改动。

### 一次 `read` 的完整判断过程

```
read(src/app.py)
  │
  ├─ 算当前磁盘文件的 SHA-1
  │
  ├─ 缓存里有记录吗？
  │    └─ 没有 ──────────────→ 存快照 + 影子，回全文          【首次】
  │
  ├─ SHA-1 和记录里的一样吗？
  │    └─ 一样 ─────────────→ read_count +1，回一行摘要        【没变】
  │
  └─ 不一样（外部改过）
       ├─ 有影子副本？ ──有──→ difflib 对比影子 ↔ 现文，回 diff + 精确变更区间   【变了】
       └─────────────── 没有 → 只能回全文（降级），并说明原因
```

最后那个降级分支是要点：**它不会假装知道改了什么**。如果影子丢了（比如文件当时超过 2 MB），它就老实说"我没有基线，只能给你全文"。

### 为什么变更行区间不是从 diff 里读的

统一 diff 的 hunk 头写着 `@@ -11,7 +11,7 @@`，意思是"从第 11 行起 7 行"，其中包含 3 行上下文 —— 真正改的可能只有第 14 行。直接拿这个当"改动范围"，会让 Agent 去读 11–17 行，等于白读 6 行。

所以区间是用 `difflib.SequenceMatcher(...).get_opcodes()` 重新算的：只取 `tag != "equal"` 的片段，映射回行号。纯删除（没插入）时退化到删除位置附近一行。

## 使用说明

技能加载时，宿主会给出本包的**资源基准目录**；脚本就在它下面的 `scripts/`。手动调用：

```bash
F="<包根目录>/scripts/fstate"

"$F" explore "handleRequest" --root .     # 定位代码：命中文件 + 定义行号 + 下一步
"$F" read src/app.py                      # 第 1 次：全文。第 2 次：一行字。
"$F" read src/app.py --mode range --start 40 --end 90
"$F" edit src/app.py --old 'return 1' --new 'return 2' --reason "修边界"
"$F" digest src/                          # 一次看整个目录的结构
"$F" state src/app.py                     # 版本 / 行数 / 读过几次 / 是否过期
"$F" hot --n 10                           # 我在反复读哪些文件？（自省）
```

包装脚本找不到 Python 时，自己指一下：

```bash
export FSTATE_PYTHON=/usr/bin/python3
```

Windows 下也可以直接跑：

```powershell
python "<包根>\scripts\fstate.py" explore "关键词"
```

### `read --mode auto`（默认）会替你做判断

| 磁盘状态 | 返回什么 |
|---|---|
| 从没读过 | 全文（超大文件自动分页并给下一页命令） |
| 读过、没变 | **只有一行摘要** —— 不回正文 |
| 读过、磁盘变了 | **只回 diff** + 精确变更行区间 |

### 一次编辑的输出长这样

```
# 已改 src/app.py  → v2  19 行  区间 14..14
--- a/app.py
+++ b/app.py
@@ -11,7 +11,7 @@
-    return {"ok": True, "uptime": 0}
+    return {"ok": True, "uptime": 42}
[确认改动不必重读全文：看局部用 --mode range --start 14 --end 14]
```

**这段 diff 就是验证**。区间 `14..14` 来自 `SequenceMatcher` 的 opcodes，不是 diff 的 hunk 头 —— 所以它不包含那三行上下文，直接指向真正变动的那一行。

## 子命令

| 命令 | 作用 |
|---|---|
| `explore QUERY` | 排序后的命中文件（带定义行号 / `★定义`）+ 命中行 + 签名 + 片段 + 下一步 |
| `read PATH` | 带缓存读：未变→摘要，变了→diff，`--mode range` 读区间 |
| `edit PATH --old/--new` | 编辑并回 unified diff + 精确变更行区间 |
| `write PATH --content-file` | 整篇写入（新建给预览，覆盖给 diff） |
| `digest PATH...` | 多文件结构总览（行数 + 签名 + 缓存状态） |
| `state PATH` | 版本 / 行数 / 读次数 / 上次编辑区间 / 是否 STALE |
| `diff PATH` | 取最近一次 diff |
| `reset PATH` | 清单个文件缓存 |
| `hot [--n N]` | 读得最多的文件排行 —— 用来照自己有没有反复读 |

`"$F" --help` 看全部参数。

## 设计要点

- **磁盘是唯一真相。** 每次读/改前先比 SHA-1。你在编辑器里改过、`git checkout` 过，下次 `read` 立刻发现并给 diff，不会拿旧内容骗人；`state` 会标 `STALE`。
- **影子副本。** ≤2 MB 的文件会留一份 `.shadow`，算 diff 不需要 git。状态文件是 `~/.dsh/fstate-cache/` 下的 `<sha1(path)[:20]>.json`。
- **编码回退。** 先认**真 BOM**（UTF-8 / UTF-16 / UTF-32，含大小端）定编码；只有在没有 BOM 时才依次试 `utf-8` → `gbk` → `latin-1`。写回保持原 BOM、原编码、原换行风格 —— 本来没 BOM 的文件永远不会凭空多出一个。超过 8 MB 或含 NUL 字节的文件直接判「不是文本」，不硬啃。**刻意不拿 `utf-8-sig` 做探测**：它对无 BOM 的纯 UTF-8 也能解码成功，旧版本正是因此给每个编辑过的文件盖上了 `EF BB BF`。
- **换行宽容。** LF 片段改 CRLF 文件（Windows 很常见）能匹配上，写回仍是 CRLF；`write` 整篇覆盖时也会把正文归一成目标文件的换行风格，不会把 CRLF 悄悄变成 LF。
- **输出有上限，但砍掉什么都告诉你。** 超长 diff 和日志会落到溢出文件，只回预览 + 路径；`--max-files` / `--max-scan` / `hot --n` 这类上限一旦生效，一定会补一行 `其余 N 个` 或 `⚠ 扫描在 N 处截断`。**看到这行别忽略** —— 答案可能就在被砍掉的那部分里。静默截断不会报错也不会算错，只会让你以为「就这么多」，这正是本工具要避免的失败模式。
- **缓存位置可搬。** `FSTATE_HOME` 换目录；`reset <path>` 清单个文件；`hot` 看都在攒什么。

## 常见问题

**Q：为什么不做成插件注册一堆工具，而是一个命令行脚本？**

两个原因，第二个更硬：

1. DSH 已经有 `read` / `grep` / `edit` / `write` 这些工具了。再注册一套功能重叠的，模型会随机挑一套用，行为不可预测 —— 这比没有更糟。
2. **工具调用是无状态的。** 注册成工具，函数每次被调用都是全新开始，上次读了什么它不知道。而 CLI 进程虽然也无状态，但**磁盘给了它跨调用的记忆**。想解决"重复读"，状态就只能落盘，那就不需要工具接口了。

**Q：会不会读到旧内容？**

不会。**每次读之前都先算当前文件的 SHA-1 和记录比对**，不一致就当"外部改过"处理，拿影子副本算 diff。它唯一可能给旧内容的情况是影子副本丢了 —— 那时它会明确说"降级为全文"，不会把旧内容当新的给你。

**Q：缓存脏了 / 想从头来？**

```bash
"$F" reset src/app.py        # 清一个文件
rm -rf ~/.dsh/fstate-cache   # 全清（无害，下次自动重建）
```

**Q：会占多少磁盘？**

每个文件一条 JSON（约 300 字节）+ 一份影子副本（≤2 MB，且只对有读过的文件）。一个上千文件的项目通常几 MB 到几十 MB。介意就 `hot` 看谁占得多再 `reset`。

**Q：Web 版 / 远程环境能用吗？**

能，只要那个环境里有 Python 3.8+ 和写权限。缓存落在 `$HOME/.dsh/fstate-cache`，各环境各自一份，互不干扰。

**Q：会不会和 DSH 自带的 `read` 工具打架？**

不会，它不改任何原生工具，只是多给你一个选择。SKILL.md 里写明了分工：**知道确切行号 → 用原生 `read`；要第二次碰同一个文件 → 用本技能。**

## 排错

| 症状 | 原因 | 怎么办 |
|---|---|---|
| `ERROR: 找不到 python` | 包装脚本没找到解释器 | `export FSTATE_PYTHON=/path/to/python3` |
| `ERROR: 未找到 old 片段` | `--old` 和文件内容对不上（空格/缩进/编码） | 用 `read --mode range` 把那段原文打出来，**复制**它做 `--old`；换行符不用管（LF 改 CRLF 文件会自动归一） |
| `old 片段出现 N 次，不唯一` | 片段太短，匹配到多处 | 加长片段（多带一行上下文），或者确实想全改时加 `--all` |
| `ERROR: 无法按文本读取（toolarge）` | 文件 > 8 MB | 用原生工具，或先切分 |
| `ERROR: 无法按文本读取（binary）` | 含 NUL 字节 | 二进制文件本技能不处理 |
| 编辑成功但下次读说"变了" | 你的编辑器在你不知情时改了（格式化、保存钩子） | `state` 看 SHA-1 和版本号，确认是谁改的 |
| 技能没出现在目录里 | 插件没装成 / DSH 未重启 | `dsh plugin --profile web list` 看在不在；重启一次 |

## 什么时候**别**用它

- 已经知道确切行号 → 原生读取工具更快，进缓存是负担。
- 一次性脚本、单条命令 → 没有第二遍，缓存零收益。
- 二进制 / 图片 / 超过 8 MB → 它按设计拒绝。

这条要说实话：**「定位一个问题 → 读一段 → 改一处 → 确认」这种只走一遍的流程，用本技能反而更贵**。实测 11276 → 13140 B·轮（亏 16.5%），因为 `explore` 比精确 `grep` 贵约 18 倍，而 `read` 带行号前缀比裸 `sed` 多几百字节。行号前缀是刻意留的（Agent 靠它精确指定编辑范围），不为省字节砍掉。

它划算的地方是**同一批内容在上下文里被反复用到**：每文件碰 4 次省 65%，改 N 处各确认一次省 88%，一次看懂 20 个文件结构省 80%。

**判断口诀：这件事会发生第二遍吗？会 → 用它；不会 → 用原生工具。**

## 兼容性

在 DSH `0.2.1-rc.5` 上验证通过。技能 provider 走 `ctx.skills.registerProvider`；宿主不传 `control` 对象时会优雅降级（改 SKILL.md 后需重启，而不是热更新）。

注册档位是 rank `600`（bundled）。如果你在 `~/.dsh/dsh-skill/file-state-cache` 也放了一份本地版，**本地版优先** —— 插件不该覆盖你自己的特化版本。
